🎯 CONTEXTE PROJET
═══════════════════════════════════════════════════════════════════════════════

Park & See - Phase 1 : Solution de gestion du stationnement dans les parkings 
publics d'une grande agglomération française.

Dashboard Agent : Interface web pour les contrôleurs (agents de mairie & police 
municipale) permettant de :
- Surveiller en temps réel les véhicules garés
- Détecter et signaler les infractions (dépassement de durée payée)
- Régulariser les infractions
- Visualiser les statistiques d'occupation

États des Réservations (ReservationStatus) :

public enum ReservationStatus {
    ACTIVE,      // Véhicule garé (en cours de stationnement)
    SIGNALE,     // Infraction signalée par un agent
    COMPLETED,   // Véhicule parti / Infraction régularisée
    CANCELLED    // Réservation annulée
}

⚠️ IMPORTANT : OVERDUE EST OBSOLÈTE - Ne plus utiliser ce statut !

Workflow des Statuts :

┌─────────────────────────────────────────┐
│ 1. UTILISATEUR RÉSERVE & PAYE          │
│    ↓                                    │
│    ACTIVE (véhicule garé)              │

                ↓
┌─────────────────────────────────────────┐
│ 2. DURÉE PAYÉE DÉPASSÉE (automatique)  │
│    ↓                                    │
│    ACTIVE (toujours, mais en excès)    │
│    Ticket apparaît dans dashboard      │
└─────────────────────────────────────────┘
                ↓
        ┌───────┴───────┐
        ▼               ▼
┌─────────────┐   ┌──────────────┐
│ 3a. AGENT   │   │ 3b. AGENT    │
│  SIGNALE    │   │  RÉGULARISE  │
│             │   │  DIRECTEMENT │
└─────────────┘   └──────────────┘
        │               │
        ▼               │
    SIGNALE             │
(badge orange)          │
        │               │
        ▼               │
┌──────────────────────┴─────────┐
│ 4. AGENT RÉGULARISE            │
│    ↓                           │
│    COMPLETED (véhicule parti)  │
└────────────────────────────────┘

Règles Importantes :
✓ Un véhicule ACTIVE peut être en excès ou non (calculé en temps réel)
✓ Un véhicule SIGNALE reste dans le parking jusqu'à régularisation
✓ Un véhicule COMPLETED disparaît des parkings et va dans l'historique
✓ CANCELLED ne compte pas dans l'occupation
✗ OVERDUE EST OBSOLÈTE : Ne plus utiliser ce statut (remplacé par SIGNALE)

Formules :
- En excès maintenant = COUNT(ACTIVE WHERE maintenant > startAt + durationMinutes)
- Déjà Signalés       = COUNT(SIGNALE)
- Régularisés         = COUNT(COMPLETED)
- Moyenne Excès       = SUM(excès) / COUNT(tickets en excès)
- Temps Total Excès   = SUM(excès de tous les ACTIVE en excès + SIGNALE)

Calcul de l'excès pour un véhicule :
excès = (maintenant - startAt) - durationMinutes

Exemple : 
  Début 10h00, Durée payée 60min, Maintenant 11h30
  excès = 90 min - 60 min = 30 min d'excès

─────────────────────────────────────────────────────────────────────────────
1. ⚠️ Statut OVERDUE Obsolète
─────────────────────────────────────────────────────────────────────────────

Problème : Le backend comptait ACTIVE + OVERDUE + SIGNALE mais OVERDUE 
           n'existe plus dans notre logique.

Solution : Supprimé toutes références à ReservationStatus.OVERDUE dans :
           - getOccupationStats()
           - getOccupationByZone()
           - findVehiclesByParking()

Code corrigé :

// AVANT ❌
List<ReservationEntity> activeReservations = 
    reservationRepository.findByStatus(ReservationStatus.ACTIVE);
activeReservations.addAll(
    reservationRepository.findByStatus(ReservationStatus.OVERDUE)); // OBSOLÈTE
activeReservations.addAll(
    reservationRepository.findByStatus(ReservationStatus.SIGNALE));

// APRÈS ✅
List<ReservationEntity> activeReservations = 
    reservationRepository.findByStatus(ReservationStatus.ACTIVE);
activeReservations.addAll(
    reservationRepository.findByStatus(ReservationStatus.SIGNALE));

─────────────────────────────────────────────────────────────────────────────
5. ⚠️ Calcul Temps Total Excès Incorrect
─────────────────────────────────────────────────────────────────────────────

Problème : Le temps augmentait en permanence car calculé en temps réel depuis 
           la fin théorique.

Solution : Calcul fixe au moment de l'affichage :

const calculateOverdueMinutes = (ticket) => {
  const now = new Date();
  const startAt = new Date(ticket.startAt);
  const endTime = new Date(startAt.getTime() + ticket.durationMinutes * 60000);
  const diff = Math.floor((now - endTime) / 60000);
  return Math.max(0, diff); // Retourne 0 si pas encore en excès
};

🔄 ENDPOINTS API UTILISÉS
═══════════════════════════════════════════════════════════════════════════════

Backend (OverdueControlController.java) :

GET  /api/agent/overdue/stats
     → Retourne les statistiques d'excès
     { currentOverdue, markedOverdue, regularized, 
       averageOverdueMinutes, totalOverdueMinutes }

GET  /api/agent/overdue
     → Retourne la liste des véhicules en infraction (ACTIVE en excès + SIGNALE)
     [ { id, licencePlate, vehicleType, startAt, durationMinutes, 
         status, address, ... } ]

GET  /api/agent/overdue/history
     → Retourne l'historique des régularisations (statut COMPLETED uniquement)
     [ { id, licencePlate, vehicleType, address, ... } ]

PUT  /api/agent/overdue/{id}/signal
     → Signale une infraction
     Change status: ACTIVE → SIGNALE

PUT  /api/agent/overdue/{id}/regularize
     → Régularise une infraction
     Change status: ACTIVE|SIGNALE → COMPLETED

GET  /api/agent/overdue/occupation
     → Retourne les statistiques d'occupation globale
     { totalActive, totalCapacity, availablePlaces, occupationRate }

GET  /api/agent/overdue/occupation/by-zone
     → Retourne l'occupation par parking
     [ { parkingName, occupiedPlaces, totalCapacity, 
         availablePlaces, occupationRate } ]

GET  /api/agent/overdue/parking/{parkingName}/vehicles
     → Retourne les véhicules présents dans un parking spécifique
     [ { id, licencePlate, vehicleType, status, ... } ]

🎯 POINTS D'ATTENTION CRITIQUES
═══════════════════════════════════════════════════════════════════════════════

─────────────────────────────────────────────────────────────────────────────
1. Calcul de l'Excès
─────────────────────────────────────────────────────────────────────────────

CORRECT ✅
excès = (maintenant - heure_de_début) - durée_payée

Exemple :
  Début: 10h00, Durée payée: 60 min, Maintenant: 11h30
  Temps écoulé: 90 min
  excès = 90 - 60 = 30 min d'excès

INCORRECT ❌
excès = maintenant - (heure_de_début + durée_payée)
// → Continue d'augmenter indéfiniment même après régularisation

─────────────────────────────────────────────────────────────────────────────
2. États Exclusifs
─────────────────────────────────────────────────────────────────────────────

✓ Un véhicule ne peut avoir qu'UN SEUL statut à la fois
✗ Pas de doublons type res-004 (ACTIVE) + res-004-sig (SIGNALE)
✓ Transition claire : ACTIVE → SIGNALE → COMPLETED

─────────────────────────────────────────────────────────────────────────────
3. Occupation = ACTIVE + SIGNALE uniquement
─────────────────────────────────────────────────────────────────────────────

✅ ACTIVE (tous, en excès ou non)
✅ SIGNALE
❌ COMPLETED (véhicules partis)
❌ CANCELLED (réservations annulées)
❌ OVERDUE (OBSOLÈTE - NE PLUS UTILISER)

Formule :
Véhicules garés = COUNT(ACTIVE) + COUNT(SIGNALE)

Code backend :
List<ReservationEntity> present = new ArrayList<>();
present.addAll(reservationRepository.findByStatus(ReservationStatus.ACTIVE));
present.addAll(reservationRepository.findByStatus(ReservationStatus.SIGNALE));

─────────────────────────────────────────────────────────────────────────────
4. Temps Réel vs Temps Fixe
─────────────────────────────────────────────────────────────────────────────

Excès individuel : Calculé en temps réel pour l'affichage
  → Augmente chaque seconde pour les tickets en cours

Temps total excès : Somme des excès calculés à un instant T
  → Pas une durée qui augmente continuellement
  → Recalculé à chaque chargement des données (toutes les 30s)

─────────────────────────────────────────────────────────────────────────────
5. Backend H2 en Mémoire
─────────────────────────────────────────────────────────────────────────────

⚠️ Les données se réinitialisent à chaque redémarrage du backend
⚠️ Véhicules ajoutés via UI disparaissent au restart
✓ Ajouter dans data.sql pour persistance entre redémarrages

Pour ajouter un véhicule permanent :
1. Éditer backend/src/main/resources/data.sql
2. Ajouter une ligne INSERT INTO reservations (...)
3. Redémarrer le backend
